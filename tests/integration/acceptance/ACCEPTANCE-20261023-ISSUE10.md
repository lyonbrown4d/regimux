## 修复行为

`internal/ecosystems/dist/service.go` 在缓存读取失败且调用方 context 仍有效时，复用现有回源下载与缓存写入流程。首次读取失败后直接回源，避免再次打开同一个慢缓存。coalescer 的 Wait 回调读取失败时采用相同处理。

调用方取消或截止时间到达时，返回可由 `errors.Is` 识别的 context 错误。不可读缓存不再作为可用 stale body；上游失败时保留真实失败响应。共享对象打开的默认 2 秒预算保持原值，未引入新依赖或增加全局重试。

缓存持续不可读期间，并发请求可能分别回源；N 个请求可能产生 N 次上游请求。本次不承诺故障期间将所有回源合并。

### Issue #10 的真实慢存储对照

本地隔离容器使用 PostgreSQL、S3 和延迟代理。对象 GET 延迟 2.2 秒，上游延迟 1.2 秒，客户端重复下载预算 5 秒。

- 原 1.3.6 镜像：预热后的重复 GET 返回 502。
- 修复候选：3.854 秒完成重复 GET，内容大小与 SHA-256 一致；只发生一次 S3 对象打开，并成功回源。
- Range 返回 206；If-Range 不匹配返回完整 200；HEAD 无正文且长度正确；不可满足范围返回 416，未额外打开对象或回源。
- 应用容器上限 512 MiB、`GOMEMLIMIT=384MiB`，无 OOM、无重启。

新增 Go 回归测试覆盖慢打开、瞬时读取失败、调用方取消与截止时间、Range/If-Range/HEAD、上游失败、16 请求并发回源及 Wait 错误分支。Wait 用例覆盖 owner 填充前的缓存预检。
